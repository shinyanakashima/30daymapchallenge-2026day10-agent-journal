# 本番セッションの記録手順

再生する対話は実際の制作会話に限ります。後から会話を書き起こしたり、要約で置き換えたりしません。

## 0. 始める前に

- 地図の題材と使用データを決める。公開条件（ライセンス、出典表記、再配布）を確認できるオープンデータに限る。個人の旅行記録などは使わない。
- データは制作モードから読める形式にしておく（GeoJSON、TopoJSON、CSV、TSV、JSON）。大きすぎる場合は範囲や属性を絞る。
- OpenAI APIキーと使うモデルを決める。

## 1. 記録を作る

1. `index.html?mode=record` を開き、ヘッダーの「制作パネル」→「新しい記録」で セッションID（例 `production-2026`）、題名、種類 `production` を入れる。
2. 「データを追加」でデータファイルを入れ、出典・ライセンス・URLを記入して保存する。試しに作るときは「サンプルデータを追加」で北海道の市町村境界と2025年国勢調査人口を入れられる。
3. APIキーを保存し、「モデル一覧を取得」でモデルを選ぶ。

## 2. 対話する

- 会話欄の下の入力欄からプロンプトを送ります。応答・コードの実行・撮影・コミットが自動で行われ、新しい工程がタイムラインと積層表示にその場で加わります。
- 描画に失敗した工程も残ります。次のプロンプトで直すよう頼んでください。
- 地図の範囲は固定したまま進めると、積層表示で変化がはっきり見えます。
- 別の画面（Claudeのチャットなど）で作った工程を混ぜる場合は、制作パネルの「APIを使わずに工程を追加」から、プロンプト・応答・画面（SVGまたは1200×900のPNG）を入れます。

## 3. 動画を撮る

公開ページではAPIキーなしで制作できないため、制作の様子は動画で見せます。

- 制作モードの画面をそのまま画面録画します（macOSなら Shift+Command+5、Windowsなら Xbox Game Bar など）。ブラウザの幅は 1440×900 前後にすると、地図・会話・タイムラインが1画面に収まります。
- 録画を始める前に、制作パネルでキーとモデルを設定して閉じておきます（キーが映らないように）。
- 積層表示（`C` キー）に切り替えると、プロンプトを送るたびに層が積み上がる様子が撮れます。
- 録画した mp4 を `public/media/` に置き、`public/sessions/index.json` の `video` に `src`、必要なら `poster` と `caption` を書きます。GitHubの1ファイルの上限（100MB）を超えないよう、長い場合は圧縮するか分けます。

### 再生の動画を自動で作る

本番の記録を `public/sessions/<id>/` に置いたあと、再生画面を自動で操作して動画にできます（ffmpeg と libx264 が必要）。

```sh
npm run build
npm run video -- <id> --lang ja --out public/media/day10-ja.mp4
npm run video -- <id> --lang en --out public/media/day10-en.mp4
```

画面表示で全工程を順に進め、積層表示に切り替えて層を積み上げ、最後に少し回転させます（1920×1080、30fps、H.264）。モデルは呼ばず、記録にあるものだけを映します。制作中の様子（入力して応答を待つところ）を見せたい場合は、上の画面録画を使います。

## 4. 公開前の確認

- 書き出し時に、APIキー・トークン・メールアドレスらしい文字列があると止まります。すべては検出できないので、本文も読んで確認してください。
- 記録（Git）は「リポジトリを書き出す」で .zip にして保管します。IndexedDBはブラウザのデータ削除で消えます。

## 5. 書き出して公開する

1. 制作パネルの「Zarrを作成してプレビュー」→「プレビューを開く」で、公開時の見え方を確かめる。
2. 「セッションをダウンロード」で .zip を保存し、`<id>/` フォルダを `public/sessions/` に置く。
3. `public/sessions/index.json` の `default` を本番の `id` に変える。fixture は残すが、本番と並べて紹介しない。
4. 書き出したリポジトリ（.zip）も `fixtures/` などに置いて、再現用に残す。
5. `npm run build`、`node scripts/verify-browser.mjs <id> --source <build-report.json のあるフォルダ>`、`npm run screenshot -- <stepId> <id>`。
6. README の「データ」「モデル情報」「Zarrの役割と限界」の数値を本番の記録で書き直す。
